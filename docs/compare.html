The 2026 agent landscape

Agent makes intelligence accountable to a goal.

It is a federation of focused programs organized around a durable outcome. GOAL.md holds the destination, Ply structures the attempts, and Ask supplies replaceable intelligence. Context, authority, proof, evidence, learning, and approval keep independent owners—so the whole worker remains inspectable and verifiable.

01 / Agent’s advantage

The seams are the system.

Most frameworks optimize the experience inside one application or runtime. Agent optimizes the boundaries around intelligence: the outcome stays stable, completion stays external, authority stays caller-owned, and every important transition leaves inspectable evidence.

01 / OUTCOME

The goal outlives the conversation

GOAL.md keeps the desired outcome and constraints durable while plans, models, and attempts can change. A separate executable check—not model confidence—decides when the work is accepted.

02 / INTELLIGENCE

The model is replaceable

Ask owns providers, credentials, structured output, and replayable sessions. Agent and Ply keep the same goal, tool, and verification contracts when the selected model changes.

03 / AUTHORITY

Instructions cannot grant power

Markdown may shape behavior, but the caller owns networking and confinement, Cage owns the OS boundary, and May binds human approval to exact bytes. The worker cannot rewrite its judge.

04 / EVIDENCE

Claims can be replayed

Ask records the conversation; Ply seals verifier results; Trail reads without repairing or rewriting. Evidence lives outside the worker’s writable roots and remains useful after the model turn is gone.

05 / LEARNING

Learning must earn admission

Hone learns only from a run that failed and later passed an executable check. Exact reviewed lessons retain provenance instead of silently turning every transcript into automatic memory.

06 / COMPOSITION

An agent is ordinary software

The home is diffable, forkable, searchable, and runnable through files, programs, pipes, and exit status. Specialists recurse through the same complete abstraction with their own goals, checks, state, and evidence.

Count the whole suite.

agent is intentionally the link step, not the entire implementation. Its real product surface is the sum of the focused contracts it composes—and each capability remains usable and testable on its own.

Compare centers of gravity—not feature counts.

“Agent framework” now describes at least four different products. The right comparison asks what each architecture makes easy, visible, portable, and trustworthy.

Hosted agent systems

A server or cloud owns sessions, persistence, channels, scheduling, scaling, and often sandboxes.

Workflow platforms

Temporal · DBOS · n8n · Dify

Independent programs make ownership visible, let each capability evolve without rewriting the rest, and allow hosted scale, retrieval, or durable workflow infrastructure to compose at an explicit boundary when the use case calls for it.

03 / Full landscape

Choose the center of gravity you actually need.

Every alternative below wins somewhere. The comparison is against Agent’s specific architecture—not a claim that one system is universally better.

04 / Focused extensions

Extend the edges. Preserve the center.

Two opportunities harden Agent’s current boundary; the rest amplify it for particular environments. They fit best as focused programs, adapters, or outer controllers so goal, proof, authority, and evidence remain independently owned.

HARDEN

Resume across process failure

Agent already preserves the goal, durable state, complete Ask event history, and verifier evidence between runs. It does not yet checkpoint and resume the exact in-flight step after a killed process.

Add a Temporal-, DBOS-, or LangGraph-backed controller adapter while Agent keeps outcome acceptance.
HARDEN

Strengthen read and secret isolation

Cage’s caller-owned write and network boundary is a major strength. A stronger deployment can also hide host-readable files, inherited environment values, credentials, and programs.

Compose a disposable workspace, narrow OS identity, and secret broker around the existing Cage boundary.
AMPLIFY

Unify observability

Ask already records complete model events; Ply seals checks; Trail exposes search, windows, lineage, and replay. A shared operational view could correlate those records with tool actions, cost, and latency.

Build one read-only OpenTelemetry exporter over the existing evidence rather than a second log.
AMPLIFY

Expand evaluation and regression

The frozen corpus proves deterministic mechanics, zero-model gates, recursive homes, and replay. Domain behavior, safety, cost, and model quality need separate representative cases.

Add an eval runner that keeps executable checks distinct from probabilistic model-quality cases.
AMPLIFY

Add typed boundary adapters

Unix processes make the suite language-neutral, inspectable, and easy to compose. Applications may still want schemas, MCP/A2A discovery, or generated client types at their boundary.

Translate at the edge; keep files, streams, and exit status as the internal public contract.
EXTEND

Publish a distributed controller contract

Specialists already have isolated context, goals, state, authority, checks, and replay evidence. Fan-out, scheduling, retries, and aggregation intentionally belong to the caller.

Make that controller seam easier to implement without inventing a second specialist abstraction.
EXTEND

Offer optional managed serving

Keeping the home independent of an API server or control plane makes it portable across shell, Git, cron, CI, desktop automation, and cloud workflows.

Offer a thin service adapter for realtime or autoscaled use without adding new Agent semantics.
EXTEND

Compose retrieval as a tool

Agent already separates curated facts, machine state, full run history, and verified procedural learning. Large changing corpora need a dedicated ingestion, retrieval, and citation plane.

Expose LlamaIndex or another retrieval system as a bounded program under tools/.
Strength test: an improvement belongs only if it preserves visible ownership. Durability belongs to a controller, retrieval to a tool, traces to a reader, hosting to a runtime, and acceptance to the operator’s check. Agent remains the link step—and inherits the strength of every part it links.

05 / Decision guide

Agent fits where outcomes must outlive the model.

Choose the architecture whose strongest property matches the dominant risk. Agent’s center is durable intent, replaceable intelligence, executable proof, caller-owned authority, and inspectable evolution.

Use Agent when…

The outcome is an artifact a command can verify.Code, reports, transformed files, reviewed patches, or bounded local operations.
You want model intelligence to be replaceable.Ask owns providers while the goal, check, tools, and evidence stay stable.
Auditability beats dashboard convenience.Definitions, mutable data, complete Ask event history, verifier receipts, learning, and approvals remain distinct and inspectable.
The worker should not grant itself authority.Network, confinement, learning admission, and definition changes remain controller or human decisions.
You operate through shell, Git, cron, or CI.A locally owned, source-controlled suite is the deployment model you want.

Choose another center—or pair one—when…

You need millions of live, stateful sessions.Let Cloudflare Agents, Agno, Google Agent Runtime, or another managed runtime own serving; invoke Agent for bounded artifact outcomes where it fits.
Automatic memory is the product.Choose Letta; use LlamaIndex when retrieval over changing corpora is central. Agent is strongest when knowledge classes and admission stay explicit.
Work must resume at the exact interrupted step.Let Temporal, DBOS, LangGraph, or Microsoft Agent Framework own durable execution around the Agent run.
You need voice, streaming UI, or provider-native tooling.Use OpenAI Agents SDK, Claude Managed Agents, Mastra, or Cloudflare as the product runtime.
Your users need a visual builder and SaaS connectors.Use n8n or Dify for the operator surface; Agent can remain a source-controlled worker behind a workflow node.
Need typed Python outputs?Pydantic AI

Schema validation, dependencies, evals, and durable integrations are native to the application model.

Need explicit agent graphs?LangGraph or Microsoft

Choose LangGraph for low-level control; Microsoft for enterprise multi-language workflows and standard patterns.

Need fast multi-agent teams?CrewAI, ADK, or Agno

CrewAI optimizes role-based composition; ADK and Agno extend further into platform operations.

Need a coding-agent platform?OpenHands or Claude

OpenHands is model-agnostic and self-hostable; Claude offers a managed provider-native harness.

Need RAG and documents?LlamaIndex or Dify

LlamaIndex gives code-first data infrastructure; Dify gives teams a visual application surface.

Need the smallest experiment?smolagents or direct APIs

Do not adopt a lifecycle system when a short ReAct loop—or one model call—is enough.

06 / Better together

Some alternatives belong around Agent, not instead of it.

These are architectural opportunities, not claims of ready-made integrations. The focused-program model makes pairing possible without surrendering ownership.

Agent + Temporal / DBOS

Durable controller

Let a workflow own crash recovery and waits while Agent still owns home validation, context assembly, confinement, and executable acceptance.

Agent + LlamaIndex

Knowledge tool

Expose retrieval as a bounded program under tools/; keep ingestion and citations out of the core compiler.

Agent + n8n / Cloudflare

Triggers and channels

Use a platform for events, schedules, realtime clients, and notifications while a separately controlled Agent run produces the artifact.

Agent + provider SDKs

Specialized intelligence

Ask already separates the model boundary. Voice, managed sandboxes, or provider-native tools can remain explicit outer integrations.

Integration caution: preserve replay evidence, idempotency, authority decisions, and the exact verifier result across every boundary.
