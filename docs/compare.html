The 2026 agent landscape

Agent is not another agent framework.

It is a federation of thirteen shipped programs around inspectable outcomes. Context and Cite give it a real external-evidence and citation-identity path; named conversation checkpoints and Tend make it a credible local durable stack. Integrated SDKs, hosted runtimes, automatic memory systems, and step-replay workflow engines still win beyond those boundaries.

01 / Classify first

“Agent framework” now describes four different products.

The most misleading comparison is a single feature checklist. Architecture determines where state lives, who owns authority, how failures recover, and what “done” means.

A / PROCESS SUITE

Focused programs

Independent executables compose through files, stdin/stdout, exit status, and the OS.

Agent is the outlier here
B / LIBRARY

Orchestration SDKs

Your application imports agents, graphs, tools, memory, and tracing behind one programming API.

OpenAI · LangGraph · ADK · Pydantic
C / RUNTIME

Hosted agent systems

A server or cloud owns sessions, persistence, channels, scheduling, scaling, and often sandboxes.

Claude · Cloudflare · Agno · Letta
D / SUBSTRATE

Workflow platforms

Durability, integration, or visual authoring surrounds whatever model loop you choose.

Temporal · DBOS · Restate · Cloudflare
Bench’s bet is architectural.Intent, design, intelligence, iteration, retrieval, citation identity, confinement, approval, evidence, learning, and durability should not silently accumulate in one runtime. Context owns normalized retrieval provenance; Cite owns literal ref-to-URL verification; Ply owns the conversation pointer; Tend owns local process state. The cost is integration work: Bench supplies fewer batteries and more visible seams.
The MCP answer is compilation, not denial.Ply’s available contrib/mcpbox discovers tools/list, reads each JSON Schema, and writes one type-aware Unix program per capability. The toolbox directory is an enforced allowlist; deleting a wrapper revokes the tool. The 0.9.0 archive does not install mcpbox, and an external bridge retains transport, authentication, session, and protocol-version ownership.

03 / Full landscape

Choose the center of gravity you actually need.

Every alternative below wins somewhere. The comparison is against Agent’s specific architecture—not a claim that one system is universally better.

Agent / Bench

process suite

A thirteen-component Unix suite spanning intent contracts, design, procedures, model sessions, connector-based external evidence, citation identity, executable completion, OS confinement, reviewed learning, local durability, and an available MCP edge adapter.

Best atLocal, inspectable, goal-driven work where retrieval provenance is explicit and an external command can prove success.
UniqueSource choice, retrieval, citation identity, model work, authority, evidence, learning, approval, and durability retain separate owners.
CostNo managed runtime, step replay, multi-host failover, native index/vector store, semantic citation judge, realtime channels, or rich application SDK.

04 / Honest gaps

Agent’s missing pieces are real—and should stay separate pieces.

The right roadmap preserves the suite’s central advantage. Fill gaps with focused adapters or programs; do not turn agent into the monolith it was designed to avoid.

P0

Step durability and effect safety

Ply can resume the conversation and Tend can recover local job state, waits, and pre-start crashes. Neither journals internal workflow steps or knows whether an interrupted external effect happened.

Add a workflow substrate when durable steps, idempotency, compensation, or multi-host recovery are required.
P0

Read and secret isolation

Cage constrains writes and network, but it does not hide every host-readable file, environment value, credential, or program.

Add a stronger disposable workspace / secret broker boundary.
P1

Unified observability

Ask sessions, verifier receipts, approval records, and Tend events are inspectable, but there is no cross-suite OpenTelemetry view of model calls, checks, actions, cost, and latency.

Create one read-only trace exporter over existing evidence.
P1

Evaluation and regression suites

The frozen corpus validates mechanics, not domain behavior, model quality, safety, cost, or task-level success rates.

Add an eval runner that treats checks and golden model cases separately.
P1

The rest of MCP and app SDKs

mcpbox compiles discovered MCP tools into an enforceable Unix allowlist. It snapshots the catalogue until regenerated; positional typing covers simple top-level schemas while complex JSON remains server-validated. Resources, prompts, tasks, apps, live catalogue changes, A2A, and a typed application client are not first-class Bench surfaces.

Keep transport and authentication in bridges; add edge adapters rather than another internal tool format.
P2

Distributed specialist orchestration

Specialists are isolated and replayable, but fan-out, scheduling, retries, and aggregation stay with an external controller.

Keep that external; make the controller contract easier to implement.
P2

Realtime and managed serving

There is no built-in API server, WebSocket client, channel gateway, autoscaling runtime, or hosted control plane.

Offer a thin optional service wrapper with no new agent semantics.
P2

Knowledge orchestration beyond retrieval

Context already discovers caller-selected executable connectors, normalizes evidence without flattening structured content, and stamps query and connector provenance. When those records are supplied to Ask, its history retains the exact cited snapshot. Cite already gates exact ref-to-URL identity. Bench still has no native index, ingestion pipeline, vector store, automatic source router, reranker, semantic support judge, or grounding policy.

Compose those higher-level data services behind Context connectors or task-specific checks; do not duplicate the evidence envelope.
Roadmap rule: a gap is not permission to grow the compiler. Tend owns local process durability; a workflow engine may own durable steps; retrieval belongs to a tool, traces to a reader, and hosting to a runtime. Agent should remain the link step.

05 / Decision guide

Use Agent when proof and boundaries matter more than batteries.

The best choice follows the dominant risk in your system: wrong output, lost state, unsafe action, missing memory, integration effort, or operating scale.

Use Agent when…

The outcome is an artifact a command can verify.Code, reports, transformed files, reviewed patches, or bounded local operations.
You want model intelligence to be replaceable.Ask owns providers while the goal, check, tools, and evidence stay stable.
Auditability beats dashboard convenience.Definitions, mutable data, sessions, checkpoints, learning, approvals, and job evidence remain inspectable.
The worker should not grant itself authority.Network, confinement, learning admission, definition changes, and ambiguous retry decisions remain controller or human decisions.
You operate through shell, Git, cron, launchd, systemd, or CI.Named conversation continuation and conservative local process supervision are enough.

Do not use Agent alone when…

You need millions of live, stateful sessions.Choose Cloudflare Agents, Agno, Google Agent Runtime, or another managed runtime.
Memory is the product.Choose Letta; use LlamaIndex when retrieval over changing corpora is the core.
Completed workflow steps must never be repeated.Use Temporal, DBOS, Restate, LangGraph, or Cloudflare Workflows; Tend deliberately stops at an ambiguous whole-process boundary.
You need voice, streaming UI, or provider-native tooling.Use OpenAI Agents SDK, Claude Managed Agents, Mastra, or Cloudflare.
Your users need a visual builder and SaaS connectors.Use n8n or Dify; an operator-facing shell suite is the wrong interface.
Need typed Python outputs?Pydantic AI

Schema validation, dependencies, evals, and durable integrations are native to the application model.

Need explicit agent graphs?LangGraph or Microsoft

Choose LangGraph for low-level control; Microsoft for enterprise multi-language workflows and standard patterns.

Need fast multi-agent teams?CrewAI, ADK, or Agno

CrewAI optimizes role-based composition; ADK and Agno extend further into platform operations.

Need a coding-agent platform?OpenHands or Claude

OpenHands is model-agnostic and self-hostable; Claude offers a managed provider-native harness.

Need RAG and documents?LlamaIndex or Dify

LlamaIndex gives code-first data infrastructure; Dify gives teams a visual application surface.

Need the smallest experiment?smolagents or direct APIs

Do not adopt a lifecycle system when a short ReAct loop—or one model call—is enough.

06 / Better together

Some alternatives belong around Agent, not instead of it.

The local Tend pairing is shipped. The others are architectural opportunities, not claims of ready-made integrations. Focused programs make both paths possible without surrendering ownership.

Agent + Tend / workflow substrate

Durable controller

Use shipped Tend for local exact-process jobs, durable waits, and conservative unknown resolution. Use Temporal, DBOS, or Restate when internal steps, distributed recovery, and orchestration must be durable.

Agent + LlamaIndex

Knowledge tool

Expose retrieval as a bounded program under tools/; keep ingestion and citations out of the core compiler.

Agent + n8n / Cloudflare

Triggers and channels

Use a platform for events, schedules, realtime clients, and notifications while a separately controlled Agent run produces the artifact.

Agent + MCP servers

Capability without hidden authority

Use mcpbox to discover and compile one program per approved tool. The bridge owns transport, auth, and protocol compatibility; the Ply toolbox controls which capabilities the model can name.

Integration caution: preserve replay evidence, idempotency, authority decisions, and the exact verifier result across every boundary.
