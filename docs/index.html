01 / The loop

Unix supplies the workplace. Bench supplies accountability.

GOAL.md holds the outcome steady. Ply runs a disciplined work/check/retry process; Ask records the complete run as an append-only event history that can reconstruct and verify every normalized model request. Programs do the work, exit status decides control flow, and Tend can durably supervise any process.

GOAL.mdDesired outcome

The durable objective and constraints. It says where the work must arrive without prescribing every solution.

drives→
plyWork structure

Keeps the goal in view, frames each attempt, runs the check, and turns rejection into useful feedback.

calls→
askIntelligence

Reasons through the current problem and produces the next candidate solution inside Ply’s structure.

yields→
bin/checkProven outcome

Accepts when the result satisfies the executable definition of done—not when the model merely says it has.

When the check rejects: evidence flows back through Ply, Ask adapts the solution, and the goal stays fixed.
  1. 01

    Aim

    The durable goal defines the outcome; rules, persona, plan, and memory shape the work.

  2. 02

    Compose

    Agent + Brief validate the home and load relevant procedures. When outside facts matter, Context + Cite keep retrieval and citation identity explicit.

  3. 03

    Solve

    Ply structures the loop and can fan out to isolated process workers; Ask supplies intelligence and records the replayable event spine.

  4. 04

    Confine

    Cage limits writes to work/ and state/; network is off by default.

  5. 05

    Verify

    The home’s executable bin/check accepts or rejects the result—not model prose.

  6. 06

    Replay + learn

    Ask, Trail, Hone, and May make requests reconstructible, evidence browsable, recovery reusable, and change deliberate.

✓

Completion is a program’s opinion. The loop ends only when bin/check exits 0. The worker cannot talk its way into being done.

02 / The complete suite

Thirteen shipped components. Thirteen visible jobs.

This is the complete Bench 0.9.0 manifest—not only the inner Agent loop. No component quietly absorbs another’s job, so the system remains easier to reason about, replace, test, and trust.

bench

▤

◎

tend

◷
event-sourced process durability

Supervises exact argv with transactional SQLite state, immutable lifecycle events, durable signals and timers, verified artifacts, projection replay, and explicit uncertain-effect resolution.

draft

△
design + promotion path

Turns an argued DESIGN.md into explicit build and proof commands, composing Ask, Brief, Ply, and Hone instead of hiding another framework.

new · check · build · prove
MCP is an edge adapter, not a fourteenth suite component. The standalone MCP edge discovers remote capabilities and produces a descriptor-admitted directory of ordinary programs. Bench and Ply consume that directory without depending on its compiler or learning the wire protocol. The edge is available today but remains outside the Bench 0.9.0 archive.
The refusals are features. Ask has no tools. Context never chooses a source or synthesizes an answer. Cite verifies literal identity, not semantic support. Ply has no model or hidden MCP session. Brief does not decide. Cage does not infer intent. Tend does not claim exactly-once effects. Each narrow contract prevents invisible authority from accumulating in one opaque runtime.

The worker can…

  • Read its definition and selected skills
  • Use the host tool catalogue and approved MCP tool programs
  • Write deliverables under work/
  • Keep mutable facts under state/
  • Propose a definition patch for review

The worker cannot grant itself…

  • Network access from Markdown
  • Writes outside its confined roots
  • A passing completion verdict
  • An automatic memory or skill update
  • Approval to change its own definition
