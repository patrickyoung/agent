01 / The loop

Goals drive outcomes. Ply gives intelligence a way to get there.

GOAL.md holds the desired outcome steady. Ply provides the disciplined work/check/retry structure and can advance one named Ask-session checkpoint. Inside each attempt, Ask supplies the model intelligence that works on a solution.

GOAL.mdDesired outcome

The durable objective and constraints. It says where the work must arrive without prescribing every solution.

drives→
plyWork structure

Keeps the goal in view, frames each attempt, runs the check, and turns rejection into useful feedback.

calls→
askIntelligence

Reasons through the current problem and produces the next candidate solution inside Ply’s structure.

yields→
bin/checkProven outcome

Accepts when the result satisfies the executable definition of done—not when the model merely says it has.

When the check rejects: evidence flows back through Ply, Ask adapts the solution, and the goal stays fixed.
  1. 01

    Aim

    The durable goal defines the outcome; rules, persona, plan, and memory shape the work.

  2. 02

    Compose

    Agent + Brief validate the home and load only the relevant context and skills.

  3. 03

    Solve

    Ply structures the loop and preserves a named conversation; Ask supplies intelligence for each solution attempt.

  4. 04

    Confine

    Cage limits writes to work/ and state/; network is off by default.

  5. 05

    Verify

    The home’s executable bin/check accepts or rejects the result—not model prose.

  6. 06

    Remember

    Trail, Hone, and May make evidence browsable and change deliberate.

✓

Completion is a program’s opinion. The loop ends only when bin/check exits 0. The worker cannot talk its way into being done.

02 / The components

Small tools. Clear ownership. Stronger together.

No component quietly absorbs another’s job. That makes the system easier to reason about, replace, test, and trust.

agent

⌘
compiler + controller

Validates the directory, assembles the run, exposes exact composition, and keeps definition, mutable work, and evidence separate.

scaffold · show · run · tick

brief

◫
context

Finds, validates, and prints the relevant written procedures and Agent Skills. It never calls a model.

rules · skills · selection

ply

↻
structure for progress

Frames attempts, runs the external check, returns feedback, retries, and durably advances one named Ask-session pointer across restarts and compaction.

attempt · check · retry · resume

ask

✦
intelligence + sessions

Calls the selected model to reason through each solution attempt and records replayable turns. It does not own the goal or completion.

reason · adapt · record

cage

▦
authority boundary

Confines model-authored actions at the OS boundary. A toolbox suggests what to use; Cage controls what can happen.

writes · network · process

trail

⌁
evidence browser

Lists, searches, windows, and replay-checks prior runs without inventing another session format or writer.

history · lineage · integrity

hone

◇
reviewed learning

Turns a verified recovery into a proposed procedure update. Learning is explicit, inspectable, and never automatic.

prepare · show · admit

may

◎
human authorization

Binds one human decision to exact proposed bytes and current state before a definition change can be applied.

review · decide · receipt

tend

◷
durable process supervisor

Supervises exact argv with local SQLite state, durable signals and timers, immutable output evidence, and explicit resolution when a started effect is uncertain.

submit · wait · work · resolve

mcpbox

⇄
Ply contrib MCP adapter

Discovers an MCP server’s tool catalogue and JSON Schemas, then writes one help-bearing, type-aware Unix program per capability for a Ply toolbox.

discover · compile · allowlist · call
The refusals are features. Ask has no tools. Ply has no model or hidden MCP session. Brief does not decide. Cage does not infer intent. Tend does not claim exactly-once effects. MCP transport stays in a bridge while mcpbox turns approved capabilities into ordinary programs. Each narrow contract prevents invisible authority from accumulating in one opaque runtime.

The worker can…

  • Read its definition and selected skills
  • Use the host tool catalogue and approved MCP tool programs
  • Write deliverables under work/
  • Keep mutable facts under state/
  • Propose a definition patch for review

The worker cannot grant itself…

  • Network access from Markdown
  • Writes outside its confined roots
  • A passing completion verdict
  • An automatic memory or skill update
  • Approval to change its own definition
