Bench suite 0.9.0 · rescanned 28 Aug 2026

Thirteen small programs. Most of a modern agent stack.

Bench reaches modern capabilities by composition. This map starts from the exact released manifest, names the job each component owns, and compares it with the widely adopted 2026 systems teams commonly use for that job.

How to read it

Equivalent capability does not mean identical architecture.

Frameworks usually combine model access, tools, state, approvals, retrieval, memory, and traces inside one SDK or hosted runtime. Bench assigns those jobs to programs connected by files, streams, literal arguments, and exit status. The comparison therefore asks whether a capability exists, who owns it, and where its guarantee stops.

Adoption note. There is no credible apples-to-apples usage census across model APIs, coding workbenches, RAG libraries, sandboxes, observability platforms, and durable workflow engines. “2026 reference points” below means prominent, widely deployed or ecosystem-visible systems with current primary documentation—not a fabricated rank order.

benchoperator workbench
Turns open intent into a visible, admitted outcome contract, then invokes the other filters. It owns the operator journey—not a second model, loop, or evidence store.
OpenAI Codex and Claude Code are the prominent integrated workbenches: task delegation, tools, review, parallel work, and long-running sessions.
Bench provides the intent → contract → task → proof path, but keeps model, tools, confinement, and history in replaceable executables. It lacks their hosted task fleet, IDE surfaces, and managed collaboration.
native, less integrated
askmodel + session boundary
Puts one question through a selected model, streams progress separately, records replayable JSONL sessions, and prints the answer. It has no tools and no agent loop.
The OpenAI Responses API and Anthropic Messages API are common model-call foundations with streaming, multimodal input, reasoning, and conversation state.
Ask provides a multi-provider local CLI and replay authority with a clean stdout contract. Provider APIs offer richer native tools and hosted state; Ask deliberately leaves both to other programs.
native, provider-neutral
briefprocedure catalogue
Finds, validates, selects, and prints Agent Skills. It does not run a skill, install it, or invoke a model.
The open Agent Skills specification, plus skills in Claude Code and Codex, are the 2026 convention for reusable on-demand procedures.
Brief implements progressive disclosure as ls, selection, and cat. Modern harnesses usually load and execute skills inside the agent runtime; Brief keeps the catalogue independently inspectable.
native standard
plytool loop + executable verdict
Lets a model use a directory of programs, returns observations, retries against an external check, and can advance a named Ask-session checkpoint.
LangGraph and the OpenAI Agents SDK are common choices for tools, loops, sessions, handoffs, guardrails, and orchestration.
Ply reaches the core loop without importing an SDK: tools are executables and “done” is another program’s exit status. It lacks graph state, typed in-process handoffs, realtime agents, and managed tracing.
native, process-shaped
contextexternal evidence seam
Runs one caller-selected executable connector, validates and normalizes its JSONL records, preserves structured content, and stamps the exact query and connector digest.
LlamaIndex data connectors are a major reference for loading many source types into retrieval and indexing pipelines.
Context already provides connector discovery, normalized evidence, stable refs, and retrieval provenance. Unlike LlamaIndex, it has no index, embeddings, router, cache, reranker, or synthesis layer; those can sit behind a connector.
native retrieval seam
citecitation identity gate
Prints a candidate byte-for-byte only when it contains at least one citation and every ctx: occurrence is the exact ref-to-URL Markdown pair present in supplied Context evidence.
LlamaIndex CitationQueryEngine is a common end-to-end cited-RAG pattern: retrieve indexed nodes and have the model generate numbered citations.
Cite is narrower and more deterministic: it verifies literal identity after generation. It does not retrieve, create citations, judge claim support, measure coverage, or establish source authority.
strong narrow guarantee
cageOS action boundary
Runs one command with caller-selected writable roots and network policy using the host operating system. It has no daemon, image, or policy language.
Docker Sandboxes and E2B are prominent agent sandboxes using isolated microVM environments, managed templates, credentials, and longer-lived sessions.
Cage provides a cheap fail-closed boundary for ordinary local programs. It is not a container or microVM: the child may still read the host filesystem and inherited environment unless an outer deployment hides them.
native, lighter boundary
mayexact human authorization
Binds a human decision to the exact bytes of one action. Decisions can park durably, and one matching grant is atomically spent once.
LangChain HITL and OpenAI Agents SDK approvals pause tool execution so a person can approve, edit, or reject it.
May has no graph or agent state; its stronger local property is the public digest over exact job/action bytes and a single-use grant. Rich frameworks offer editable decisions and in-context continuation.
native exact-byte gate
honereviewed procedural learning
Extracts a lesson only from a replayable fail-then-pass recovery, prepares exact proposed skill bytes, and admits them only after separate review.
Letta memory blocks and LangGraph long-term memory represent the common 2026 approach to persistent, recallable agent memory.
Hone does not remember every conversation or retrieve by similarity. It trades automatic personalization for verified provenance, narrow procedural lessons, explicit proposals, and human admission.
native, review-first
trailread-only evidence browser
Lists, searches, windows, follows lineage, and requests replay checks over Ask archives without writing or indexing another history.
LangSmith is a widely used agent tracing and evaluation platform; OpenTelemetry is the cross-vendor telemetry convention.
Trail gives portable local inspection and replay integrity with no service. It does not collect cross-suite spans, costs, latency, metrics, dashboards, alerts, or online evaluations.
native archive view
agentfolder-shaped worker
Compiles a home of goal, instructions, skills, tools, state, checks, specialists, and evidence into existing Bench process boundaries.
The OpenAI Agents SDK, Google ADK, and LangGraph are major general agent runtimes.
Agent reaches instructions, tools, sessions, specialists, checkpoints, approvals, and learning through files and executables. It has no imported model client, application SDK, API server, realtime channel, managed deployment, or graph runtime.
native, filesystem-shaped
tenddurable local process supervisor
Persists exact argv in SQLite, claims work atomically, records immutable attempt evidence, waits on timers or signals, and makes ambiguous started effects require explicit resolution.
Temporal, DBOS, and Restate are the leading 2026 durable-execution references for step journals, long waits, retries, and distributed recovery.
Tend provides real crash durability for any Unix command without turning it into workflow code. It is deliberately single-host and whole-process: no step journal, multi-host workers, replayed calls, compensation, or exactly-once effect claim.
native local / outer for distributed
draftdesign → build → prove
Creates an argued DESIGN.md with an executable check, then composes Ask, Brief, Ply, and Hone for building, proof, and durable lessons.
GitHub Spec Kit is a prominent 2026 spec-driven development harness: Spec → Plan → Tasks → Implement across many coding agents.
Draft offers the same intent-before-implementation direction with far less machinery. Its center is an ordinary design document and a command’s verdict, not templates, agent integrations, catalogues, or a full SDLC harness.
native, deliberately small

What the map says

Bench is modern in capability, unusual in ownership.

The suite is no longer missing whole capability families. Its remaining gaps are mostly the capabilities that require a distributed runtime, a managed data plane, or a product-serving surface.

Strong today

Local, inspectable agent work

Bench covers model access, standard skills, a tool loop, executable completion, external evidence, citation identity, OS confinement, approvals, replayable history, reviewed learning, folder-shaped workers, design promotion, and crash-durable local processes.

Different by design

Capabilities stay separate

Popular frameworks make integration easier by owning the whole runtime. Bench makes each consequential seam independently runnable and reviewable. That costs orchestration code, but avoids invisible authority and provider lock-in.

Still outside

Distributed and managed planes

Bench does not provide multi-host step replay, a vector/index pipeline, automatic memory, semantic citation judgment, unified OpenTelemetry, realtime serving, autoscaling, or a hosted control plane. Those remain outer systems or focused future adapters.

Protocol edge

MCP support is real, but not a fourteenth component.

Ply’s source tree includes contrib/mcpbox, which discovers an MCP server’s tools/list catalogue and generates one ordinary executable per tool. That provides an explicit directory allowlist while a bridge owns transport and authentication. The Bench 0.9.0 archive does not install mcpbox, and Bench does not yet expose MCP resources, prompts, tasks, apps, or live catalogue changes as first-class surfaces. Compare that boundary with the current MCP server concepts.
